# BlueClipboard

Нативный менеджер буфера обмена для Windows 10/11 x64. C# + WPF, SQLite из состава Windows. Без Electron, серверов, телеметрии и загрузки зависимостей.

## Запуск

Запустите **`dist\BlueClipboard-Setup-x64.exe`**. Установщик добавляет ярлык в меню «Пуск» и предлагает включить автозапуск. Нужны Windows 10/11 x64 и .NET Framework 4.8. Приложение работает с обычными правами пользователя.

- **Ctrl+Shift+V** — открыть историю BlueClipboard из нужного приложения. Выберите запись, нажмите **Enter**, кнопку «Вставить» или дважды щёлкните по записи.
- **Win+V** по умолчанию открывает историю Windows. В настройках можно включить открытие BlueClipboard по этому сочетанию.
- Кнопка «Развернуть» и двойной щелчок по заголовку переключают размер окна. При восстановлении возвращаются прежние размер и положение.
- **↑ / ↓** — выбрать запись, **Ctrl+F** — поиск, **Esc** — скрыть панель.
- **Ctrl+Shift+C** или кнопка копирования — положить выбранную запись в буфер без вставки.
- Крестик скрывает окно. Для полного выхода используйте меню значка в трее → «Выйти».
- Автозапуск можно изменить в настройках приложения.

Если панель открыта из трея или сразу после запуска, она предлагает копирование: откройте целевое приложение и нажмите Ctrl+V.

## Что сохраняется

Обычный Unicode-текст с переносами строк и изображения PNG/Bitmap, включая скриншоты. Изображения сохраняются без потерь; при вставке предоставляются PNG и стандартный формат Bitmap для Paint и других редакторов. HTML/RTF преобразуются в обычный текст, если приложение предоставляет текстовый формат. Файлы, аудио и прочие специальные форматы не поддерживаются.

История переживает перезапуск. Повторные копирования одинакового содержимого обновляют существующую запись. Поиск работает по всему тексту и имени приложения, без учёта регистра, включая кириллицу. Список загружается порциями по 100 записей; есть фильтры по типу, закрепление, удаление и пауза записи.

По умолчанию сохраняются **20 000 записей / 2 ГБ содержимого**, без ограничения по возрасту. Лимиты можно изменить или отключить. При достижении лимита удаляются самые старые незакреплённые записи. Закреплённые записи могут превышать лимит. Фактический размер SQLite больше размера содержимого: в базе есть поисковые данные, индексы и служебные страницы; свободные страницы используются повторно. «Очистить незакреплённое» также уплотняет базу.

Для защиты от случайного исчерпания памяти одна запись ограничена 8 млн символов или 40 мегапикселями. Об ограничении и ошибках чтения/записи сообщается внизу панели. При быстром обновлении или длительной блокировке буфера внешним приложением промежуточную запись иногда невозможно прочитать — гарантировать захват абсолютно каждого изменения Windows не позволяет.

## Данные и поведение Windows

История: `%LOCALAPPDATA%\BlueClipboard\history.db`. Для резервной копии выйдите из приложения через трей и скопируйте папку. Дополнительные файлы `-wal` и `-shm` относятся к SQLite.

База **не зашифрована** и может содержать пароли и личные данные, которые вы копируете. Приложение уважает маркеры `ExcludeClipboardContentFromMonitorProcessing` и `CanIncludeInClipboardHistory=0`, если источник их выставляет. Автоматического распознавания секретов нет. Пауза прекращает запись новых изменений.

В настройках есть кнопка «Проверить обновления». Установленная версия по умолчанию проверяет стабильные GitHub Releases в фоне и применяет обновления, когда панель закрыта. Перед запуском установщика приложение сверяет SHA-256 файла с данными GitHub. Публичный релиз должен содержать файл `BlueClipboard-Setup-x64.exe` и иметь тег вида `v1.2.0`. Пока релизов нет, ручная проверка показывает соответствующее сообщение. История хранится отдельно от установленных файлов.

Автовставка возвращает фокус исходному окну и отправляет Ctrl+V. Если фокус вернуть не удалось, запись остаётся в буфере для ручной вставки. В приложения с более высокими правами (например, запущенные от администратора) Windows может блокировать автоматический ввод: используйте Ctrl+V вручную. Конкретное приложение само решает, какие форматы оно умеет вставлять.

## Сборка и проверки

В PowerShell из папки проекта:

```powershell
.\build.ps1
.\tests\run.ps1
.\release.ps1 -Iscc "C:\путь\к\ISCC.exe"
```

Сборка использует встроенный `C:\Windows\Microsoft.NET\Framework64\v4.0.30319\csc.exe`; .NET SDK и NuGet не нужны. Результат сборки — `dist\BlueClipboard.exe`, конфигурация и модуль обновлений рядом. `release.ps1` использует Inno Setup и собирает локальный установщик.

Автотесты проверяют SQLite, перезапуск, Unicode/кириллицу, буквальный поиск, защиту SQL-параметров, дубли, закрепление, удаление, ограничения памяти, PNG, параллельные записи, x64-структуру SendInput, XAML, запуск окна и асинхронный предпросмотр. Результаты — в `artifacts`.

```powershell
.\dist\BlueClipboard.exe --demo        # Тестовые записи без мониторинга и перехвата клавиш
.\dist\BlueClipboard.exe --background  # Запуск сразу в трей
.\dist\BlueClipboard.exe --data-dir .\artifacts\sandbox-history
```

`tests\ClipboardProbe.cs` — отдельное тестовое окно для проверки реального копирования и вставки. Оно не входит в приложение.

## Устройство проекта

- `src/Store.cs` — SQLite, поиск, история, лимиты.
- `src/ClipboardService.cs` — события буфера, повторы при блокировке, фоновая запись, PNG.
- `src/Native.cs` — Win32, сочетания клавиш, восстановление фокуса и ввод.
- `src/MainWindow.xaml` — интерфейс Windows 10.
- `src/Program.cs` — окно, трей, настройки и жизненный цикл.
- `src/SelfTests.cs` — проверки на изолированной базе и демонстрационные данные.

Использованные документы Microsoft: [изменения буфера](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-addclipboardformatlistener), [системные сочетания](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-registerhotkey), [ограничения SendInput](https://learn.microsoft.com/en-us/windows/win32/api/winuser/nf-winuser-sendinput).
